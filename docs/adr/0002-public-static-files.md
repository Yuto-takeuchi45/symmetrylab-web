# ADR 0002: 静的ファイルは許可リストに載せたものだけを配信する

- 日付：2026-11-24
- 状態：採用（依頼者指示：「サイトのページと画像だけを配信するようにして」）

## 背景・課題

- `server/app.py` は、リポジトリのルートを丸ごと静的ファイルとして配信していた（`StaticFiles(directory=リポジトリのルート)`）。
- その結果、本番で次のファイルが誰でも取得できる状態だった（2026-11-24 に確認）。
  - サーバーのプログラム（`/server/app.py`）
  - デプロイ設定（`/render.yaml`）
  - 紹介コードの一覧（`/server/referral_codes.json`）
  - テスト、社内向けの資料（`*.md`）、広告の下書き
- 顧客データのDBは永続ディスク上にあるため、配信対象外だった（`/bookings.db` は404）。

## 採用した設計

`server/app.py` の `PublicStaticFiles`（StaticFiles の派生クラス）と `is_public_static_path` で、次の条件をすべて満たすものだけを配信する。満たさないものは404にする。

1. パスのどの部分も「.」で始まらない（`.git`、`.env`、作業用の隠しフォルダを除外するため）。
2. 先頭のフォルダが `PRIVATE_STATIC_DIRS` に入っていない。対象は server、tests、docs、downloads、ad_creative、work、drafts、_review_tmp、__pycache__。
3. ファイルであれば、拡張子が `PUBLIC_STATIC_EXTENSIONS` に入っている。
   - ページ：.html
   - 画像：.png .jpg .jpeg .gif .svg .webp .avif .ico
   - ページの表示に必要なもの：.css .js
   - または、`PUBLIC_STATIC_FILES` に入っている（robots.txt のみ）。

補足：

- FastAPI の自動ドキュメント（`/docs`、`/redoc`、`/openapi.json`）は無効にした。管理系APIの一覧と仕様が誰でも見られる状態だったため。
- 非公開フォルダ名は、大文字・小文字を区別せずに判定する（macOS などでの `/SERVER/` による回避を防ぐため）。
- `follow_symlink=False` を固定している。シンボリックリンクを解決したうえで判定させるため。
- 判定は、Starlette が解決した実際のファイルの位置で行う。そのため `../` やシンボリックリンクでの回避はできない。
- `/career-check/`、`/recruitment/jobs.json`、`/sitemap.xml`、`/blog/` など、個別のルートで返しているものは、この制限の影響を受けない。

## 検討した代替案

1. **公開用ファイルを `public/` フォルダへ移し、そこだけを配信する**
   - 構成としては最も明快。
   - ただし、全ページの相対パス、LP、ブログ記事内の画像参照、管理画面の参照の書き換えが必要で、変更範囲が大きい。
   - 今回は公開範囲の是正を優先して採用しない。将来、構成を整理するときの候補とする。
2. **公開してはいけないものを列挙する除外リスト方式**
   - 新しいファイルや資料を追加したときに、うっかり公開されるおそれがある。
   - 許可リスト方式なら、追加し忘れても「公開されない」側に倒れるため、こちらを採用した。

## 採用理由

- 既存のページ・URL構成を一切変えずに、公開範囲だけを絞れる。
- 許可リスト方式なので、今後リポジトリにファイルが増えても、意図せず公開されない。

## 運用上の注意

- 新しい種類のファイル（フォント、PDF、動画など）をサイトで公開したいときは、`PUBLIC_STATIC_EXTENSIONS` か `PUBLIC_STATIC_FILES` に追加する。追加しない限り404になる。
- `downloads/case_interview_framework.pdf` は、どのページからもリンクされていないため非公開にした。公開する場合は、配置場所と許可リストを見直す。
- 管理画面のHTML（`manage-*.html`）は、従来どおり配信される。管理系のAPIは管理キーで保護されている。
