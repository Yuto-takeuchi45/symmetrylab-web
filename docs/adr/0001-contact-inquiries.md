# ADR 0001: HPのお問い合わせをDBに保存し、管理画面の「お問い合わせ」タブで管理する

- 日付：2026-11-24
- 状態：採用（依頼者承認：案A「お問い合わせタブを追加」）

## 背景・課題

- お問い合わせページ（contact.html）のフォームは、Netlify Forms 用の書き方（`method="POST" netlify`）のまま残っていた。
- 本番は Render 上の FastAPI が静的ファイルを配信しているため、送信先がなく、本番でも 405 が返っていた。お問い合わせはDBにもメールにも届かず、失われていた。
- HP改善（2026年11月分）の指摘で、サービスページの一番下にコンサルティング事業のお問い合わせフォームを追加することになった。

## 採用した設計

- 既存の顧客データDB（`DB_PATH`、本番は永続ディスク `/var/data/bookings.db`）に、次の2つの表を新しく追加する。既存の表には手を加えない。
  - `contact_inquiries`：お問い合わせ本体。`form_type` で送信元を区別する（`general`＝お問い合わせページ、`consulting`＝サービスページのコンサル相談）。
  - `contact_inquiry_status_history`：対応状況の変更履歴。
- API（`server/app.py`）
  - `POST /api/contact/inquiries`：受付。送信元の Origin を確認し、入力内容を検証して保存する。
    - 隠し項目 `website` が入力されていたらボットとみなして受け付けない。
    - 選択肢がフォームの値と一致しない場合も受け付けない。
    - `client_submission_id` が同じ送信は1件として扱い、二重送信を防ぐ。
  - `GET /api/admin/contact/inquiries`：一覧（1回500件まで、ページ送り可）。
  - `PATCH /api/admin/contact/inquiries/{id}`：対応状況（新規／対応中／対応済み／対象外）と管理メモを更新する。
  - `GET /api/admin/contact/inquiries/export`：CSV出力。
  - 管理系のAPIは、既存の申込管理と同じく `X-Admin-Key` ヘッダーで認証する。
- 通知：保存後、バックグラウンドで社内（`CONTACT_NOTIFICATION_EMAIL`、既定は info@symmetrylab.jp、カンマ区切りで複数指定可）と送信者に、受付メールを送る。送信は既存の `send_email`（Resend優先）を使う。
- 画面
  - 共通の送信処理 `js/contact-form.js` を、contact.html と services.html で使う。
  - 管理画面（manage-*.html）に「お問い合わせ」タブを追加する。処理は `js/contact-inquiries-admin.js`。既存のタブは変更しない。
- 日時は UTC の ISO 形式（`+00:00` 付き）で保存し、管理画面とメールでは日本時間で表示する。

## 検討した代替案

1. **メール通知だけにする（案B）**
   - DBの変更がない点が利点。
   - 一方で、メールの不達や見落としがあると記録が残らない。対応状況の管理もできない。
   - 依頼者は、管理画面で顧客データを管理する運用を求めているため、採用しない。
2. **既存の「キャリア相談・広告リード」タブにまとめて表示する**
   - 講座・コンサルの問い合わせと、転職相談のリードが混在する。対応状況の選択肢も合わないため、採用しない。
3. **外部のフォームサービス（Netlify Forms、Googleフォーム等）を使う**
   - 顧客データがDBと管理画面の外に分散するため、採用しない。
   - 本番は Netlify ではないので、Netlify Forms はそもそも動かない。

## 採用理由

- 既存の申込（コンサル転職相談など）と同じ仕組みに合わせている：DB保存、管理画面、`X-Admin-Key` 認証、`send_email`、二重送信防止、状況履歴。そのため保守がしやすく、運用者が覚えることも少ない。
- 新しい表を足すだけなので、既存の予約・申込データに影響しない。`CREATE TABLE IF NOT EXISTS` を使うので、再起動しても安全。
- 通知が失敗しても、内容はDBに残り、管理画面で確認できる。失敗はサーバーログに記録する。

## 運用上の注意

- 社内通知先を変えるときは、Render の環境変数 `CONTACT_NOTIFICATION_EMAIL` を設定する。
- メールが届かない場合は、Render のログで `[お問い合わせ]` の行を確認する。届いていない間も、内容は管理画面で確認できる。
